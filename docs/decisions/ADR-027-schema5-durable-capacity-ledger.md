# ADR-027：Schema5 持久容量账目基础

日期：2026-10-17。状态：C3A自动验收完成。见[验收矩阵](../plans/N-029-C3A-ACCEPTANCE.md)和[阶段证据](../evidence/n029-c3a-2026-10-17.json)；阶段提交/推送以Git及外部发布收据为准。

## 问题与范围

原生上传、复制各自的短期预留，与回收日志的 retained 费用没有共同的整树额度。网页内存 fixture 的 64MiB 计量不能作为原生持久容量依据。C3A 先新增数据库账目，不把两个不同的物理资料库接成一个，也不新增文件效果、执行 RPC、列表或网页入口。

新增 0005、Schema5 及 capacity_scopes/capacity_allocations 两表；已发布 0001–0004 保留原字节。一个数据库只允许一个 metadata_only 范围，持久固定实例、代次、原始 UTF8 主体、数据库、宿主、资料库和来源摘要。宿主 API 另核对当前身份，拒绝重绑、重复主体、读者和恢复模式写入。此元数据范围不证明物理目录身份、已盘点对象或真实可用空间；物理注册和旁路拒绝由 C3B 实现。

## 守恒和状态

总分配是全部非 cancelled 行的 declared_bytes 之和。initial/upload/copy 共用固定 64MiB，单条 0..16MiB、64 条终身历史及 8 个未终结预留；零字节仍占槽。原始业务键和意图摘要固定幂等身份，取消后同键仍返回原行。每个 allocation 的 revision 是自己的 CAS 域，与 entry、operation 计数互不排序。

reserved → armed → owned，或 reserved → cancelled。只有尚未 armed 的元数据预留能取消。armed 表示可能已有外部效果，保持全部费用并阻止新准入；重新建立实例或 SQL 连接不清空。owned 没有释放入口，未来回收和恢复都必须保留此分配，不能因 entry 的回收费用 released 就放出整树容量。没有到期清扫、永久删除或自动认领未知文件。

C3A 的显式 MetadataOnly 方法仅建模数据库转换，不构成文件发布或正面现场证明。未来物理执行者必须使用独立批准、固定根和封闭的现场凭据，不能把这些方法直接作为真实执行完成 setter。出现 capacity-registration.json 时，这条 MetadataOnly 路径直接拒绝。旧文件执行批准及内部 journal 另固定构造时的数据库版本，不能跟随原地升级。

准入与既有文件日志共用数据库级事务 advisory lock，上传与复制不能分别消费同一余额。Schema5文件日志的新准入同时预留容量行的最坏空间。所有短事务强制 synchronous_commit=on 并要求 fsync/full_page_writes；不修改数据库默认设置。准备时预留最坏终态行空间，armed 后的唯一有界状态写入不再聚合可能继续增长的旧任务数据；实际数据库错误仍保留未解决费用。

## 验证、摘要及可携

新表进入 14 表 SHARE 屏障、完整 UTC 摘要、逐行大小预检、最坏行容量、严格列/约束/索引/函数指纹及全部套件权限拒绝。验证重新运行封闭 CHECK 函数，不能因恢复了函数正文就信任曾在弱校验下写入的行。1–4 的摘要投影保持原语义。孤立升级保留旧库；导入仅在 bootstrap 收紧八个封闭函数的 PUBLIC EXECUTE。

任何 scope 或 allocation 历史，包括空范围和全部 cancelled，都拒绝普通可携导出、升级发布与回退；数据库诊断快照可以保留这些元数据，但不包含 payload，也不授予恢复写入。旧任务及具名读取客户端允许 Schema3/4/5，连接内版本仍固定；静态网页仍仅使用 Schema3 内存 fixture。

本阶段需要新定向及新未过滤原生、独立 CLI 管道、Schema5 CLI 演练、前端和需求来源核对。历史浏览器、抽象模型、编译和旧 391 项结果均不能替代新回归。按用户要求不启动浏览器或预览，不连接正式 NAS。
