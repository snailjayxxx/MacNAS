# ADR-009：桌面业务数据校验与连接生命周期

2026-10-15（Asia/Tokyo）。在N-014通用消息层之上增加bridge-client.js，不改变Swift、PostgreSQL Schema或静态网页的演示模式。

具名客户端先读取并校验overview，再固定userID、role、mode。只接受fixture-host、Schema 3、已知角色/模式，物理池仍为unbound，时间可用标记必须为false。逻辑容量等于当前有权资料库的估计值之和；后续身份、角色或模式变化使连接失效。此为防错与数据边界，不能代替宿主认证和逐次资源授权。

逐项校验任务、事件、资料库、文件和文本DTO，拒绝未知字段、错误类型、越界数值、错误受众、任意翻译键及相互矛盾的状态。标签标题、文件名、预览文本均为普通字符串，递归冻结返回值，不提供HTML渲染。只检查真实字段，不补造任务更新时间或实盘容量。目录/文本客户端验证为合成响应测试；真实目录访问仍由既有Swift描述符测试覆盖，尚无浏览器端文件链路。

每个客户端使用crypto.randomUUID生成独立请求前缀；同一宿主上重建客户端也不会从desktop-1开始重放。通用层单个适配器最多4096次请求，宿主总预算仍为4096，重建客户端不能提高宿主限额。前缀不是会话或认证凭据。

默认15秒等待、32个并发请求，配置范围1至60000毫秒及1至128个并发。超时、主动取消、关闭、非法响应或传输不可用使客户端失效，取消剩余等待并丢弃迟到结果；业务denied/readOnly等拒绝保留连接。传输收到AbortSignal，closeTransport可选回调负责释放调用方拥有的实际通道；不提供网络连接、自动重连或自动重试。取消机制参考[DOM Standard](https://dom.spec.whatwg.org/#aborting-ongoing-activities)。本实现只结束客户端等待并发送取消信号，无法强制不配合的传输停止，也不会回滚已提交的数据库任务；定时器依赖JavaScript事件循环，不是OS硬实时限制。

prepareLabelJob只在一次明确新操作时生成id/key/value，返回不可变意图。响应丢失后调用方保留该意图，用新请求ID和原业务键/值重试；服务端可以返回原任务ID。真实管道演练先确认Swift已提交任务，再故意扣留响应使客户端超时，重新连接后仍只得到一个原任务。不能把超时界面当数据库操作未发生。

事件按升序验证，映射事件类型与状态，校验相同序号的重放内容。最多32个消费者，每个保留最多100条未确认记录，同一消费者一次只允许一个轮询/确认。确认只能使用本客户端已交付的序号或当前已确认位置，成功后才删除历史；宿主继续校验实际数据库交付范围。客户端关闭不清理数据库游标。

bridge-client.js目前不加入index.html或静态预览路由，纯Node和stdin/stdout集成验证不等于网页窗口验收。用户再次明确要求回家后测试，W01–W10及完整浏览器清单继续全部未执行。下一阶段需处理客户端与DOM之间的数据/错误展示，以及任务、事件和大目录分页；生产身份、真实磁盘及宿主信任仍另行设计。
