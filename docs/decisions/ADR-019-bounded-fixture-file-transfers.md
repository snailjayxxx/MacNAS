# ADR-019：批准目录内的有界文件传输

日期：2026-10-16。接续ADR-018，实施范围为N-025原生协议和N-026文件中心流程。PostgreSQL18.6/Schema3不变，无新依赖或业务监听。最终执行结果见N-025/N-026证据，不将本文设计视作测试通过。

## 决策与范围

先建立上传预览→明确确认→分块背压→摘要校验→不覆盖发布→目录重读，以及下载固定来源→分块读取→整体校验→用户保存的闭环。现有stdin/stdout协议只用于受控原型，不扩成生产大文件通道。原请求64KiB、每字符串4096字节、响应1MiB和每连接4096次请求的预算保持不变。

| 资源 | 固定预算与生命周期 |
| --- | --- |
| 原始数据块 | 32KiB；每块最多16段、每段2048原始字节的规范base64，文本每段不超过2732字节 |
| 单文件 | 0至16MiB；这是原型上限，不是大型NAS规模或吞吐验收 |
| 活动能力 | 每API最多8个上传预览、上传或下载，共享上限 |
| 上传暂存预留 | 每API最多64MiB，按完整声明大小预留；不等于系统剩余空间或跨进程配额 |
| 时间 | 预览30秒、活动空闲60秒、绝对存活30分钟；按请求惰性回收，无后台清扫定时器 |
| 结果 | 最多32条、终止后300秒；仅原API宿主内存，不跨进程或重启 |
| 浏览器保存缓冲 | 最多16MiB和513个块引用，校验成功后创建Blob；失败/取消清空，替换/窗口关闭撤销对象URL |

零字节文件不发送上传块，完成时核对空摘要；下载以空parts的EOF块结束。上传最后一块之外必须正好32KiB，偏移必须与已确认位置相同；只允许最后一个相同块的显式重放，不能更改内容或跳跃偏移。固定预算错误、断连和超时不会自动重连或重交。

## 授权与目录身份

下载要求已经由宿主批准的内容读取，继续受用户、角色、恢复模式、卷和挂载身份约束。上传另需开发管理员、readWrite绑定以及新的宿主调用`authorizeFixtureLibraryUploads`；目录读取和mkdir/rename批准都不能代替上传批准。没有桌面批准根路径、设置权限或访问任意宿主路径的方法。

能力绑定会话UUID、实例UUID/代次、数据库名、用户原始UTF-8字节、角色/模式、资料库/相对路径、卷/介质/挂载/批准UUID、盘点修订及内容读取器UUID，上传再绑定独立批准UUID。重新批准、撤权、实例代次或来源变化后，原能力不能继续读取或发布。状态查询不会授予新的写入/读取能力。未知和其他会话的状态统一为notVisible及空元数据。取消仅释放本会话私有暂存或打开句柄，允许撤权后的原主体清理，不能回滚已发布目标。

## 上传与外部效果

预览沿用有界父目录扫描、名称规范化冲突检查和完整父标记。每次写入和发布重新核对父目录及授权。暂存固定为实例`host-binding/transfer-staging/upload-<随机UUID>`，目录0700、当前UID、文件0600、单链接；使用描述符相对的NOFOLLOW与CREAT/EXCL，拒绝链接、替换和跨文件系统。最终同卷`renameatx_np(RENAME_EXCL)`不会覆盖已存在目标，没有复制到其他设备的隐式回退。文件、目标目录和暂存目录分别fsync；fsync前后均核对发布前条件。

边收块边维护CryptoKit SHA256，发布前再用32KiB缓冲重读暂存内容，核对客户端整文件摘要与流摘要。写入检查短写、EINTR和错误；磁盘满等失败会清理仍属于自己的私有暂存。未知、替换、被移动的对象不能由清理逻辑删除。进程正常结束会释放拥有的对象；崩溃遗留暂存不自动删除，需要后续明确的恢复/孤儿处理设计。配额仅对当前API负责，不能声称重启后仍完整计量。

系统调用成功后，任何来源/授权/文件或目录同步核对失败都记为uncertain，保留摘要及进度，不能记为failed并暗示没有效果。再次finish仅返回绑定同一摘要的已有短期结果，不再次发布；取消也不删除目标。结果丢失且原宿主还可查询时，UI只允许明确核对；若新宿主返回notVisible，这不证明未执行，应先重读目录。当前没有持久审计、文件任务表、外部提交日志或重启恢复。未来需要这些语义时必须新增版本化迁移，不改0003或冒用数据库内事务的幂等保证。

发布后的核对在目录同步前后比较目标名称、描述符、原inode/设备、权限/链接数/大小和原修改时间；rename导致的预期ctime变化不直接作为内容改变。同步返回后再检查当前范围与期限。测试明确复现过“同长度改写仍被标完成”的初版缺陷，修复后归为uncertain并保留改变后的文件，不自动删除或恢复旧内容。此检测仍不是抵御敌对本机进程的原子fencing。

## 下载与客户端

下载固定打开的常规单链接文件及其父目录，限制同设备；每块读取前后检查完整内容标记和原名称，拒绝同名替换、内容修改、链接或目录变化。它是带变化检测的读取，不是文件系统快照，也不提供敌对本机进程的强fencing。响应编码在偏移/摘要前进前完成；编码预算失败不会消费该块。仅最后一块可重放，EOF后的缓存是历史数据，不能借它重新读取变化后的文件。

具名客户端保存自己的预览/下载头和偏移，按同ID串行操作；普通状态观察不能创建写入、取消或读取权。提交失败后不从观察到的新偏移自动续传。UI每次只等待一块及其接收端完成，块之间让出事件循环，取消在安全块边界生效；发布阶段没有撤回承诺。JavaScript增量摘要使用固定64字节工作缓冲，与Node crypto独立比较，同时在实际Swift管道核对CryptoKit结果，不安装第三方包。

文件中心保留原目录树，上传二进制与文本进入同一来源，发布后使旧分页失效。合成演示是有明确上限的内存数据；原生管道单独操作新建的合成APFS文件，两者都不连接家庭NAS。保存入口在完整校验后出现，需用户点击，创建/替换/关闭时管理对象URL；对象URL与文件选择器的实际浏览器行为仍单列待测，模型与DOM结构替身不能替代浏览器。
