# ADR-018：建文件夹和同目录重命名的预览/确认流程

2026-10-16，N-024。交付一条实际文件操作流程：选择已批准的合成资料库/目录、输入名称、查看冲突预览、确认应用、查看结果并重新读取目录。当前仍无生产NAS服务或浏览器到Swift的实际接线；网页样例只改内存树，文件系统证明另由显式批准的Swift测试宿主提供。

## 本阶段的取舍

建文件夹和同目录重命名作为短同步操作执行，不伪装成数据库中已入队的异步任务。现有PostgreSQL 18、Schema 3及SQL迁移保持；操作结果是每API宿主有界、短时的内存回执，不是持久任务表或数据库替代品。上传/下载、跨卷移动、回收站、重启后的持久结果与外部副作用恢复需要后续完整设计，不能把数据库任务的事务保证套用到文件系统。

## 授权与来源

原有内容批准仍只允许读取。新增宿主专用authorizeFixtureLibraryMutations，须开发模式管理员、readWrite卷绑定和已有内容根批准同时成立。该方法不在桌面消息白名单，不通过来自网页的根路径、用户或布尔标志自动批准；正式CLI也没有新增自动批准选项。

写入批准独立绑定卷批准ID、内容reader身份及新随机批准ID。重新批准内容、撤销/重绑、清单修订或身份/权限变化会失效。预览再绑定API注册会话、实例/代次、数据库配置、原始用户/角色/模式、逻辑资料库/父目录、卷/介质/挂载、内容及写入批准。即使操作只写文件，实例重绑也不能继续用旧预览。

## 描述符与不覆盖

每个待确认计划持有一个已验证的父目录描述符、父目录标记及重命名源条目标记；最多32个预览、30秒单调期限。逐级openat/O_NOFOLLOW、设备/类型/链接数和库根身份复查沿用既有边界。预览扫描整个直接父目录，8192项/1MiB名称/5秒预算，拒绝页外危险条目和规范化/大小写碰撞。

仅接受单个新名称，最多255 UTF-8字节；父路径有界，不接受任意宿主根、跨目录移动、覆盖或自动重命名策略。原名不变返回unchanged；名称或规范化/大小写等价目标已存在返回conflict，不签发可执行预览。当前不支持仅改变大小写/Unicode形式的重命名。

执行前复查批准、期限、父目录及源内容标记。创建用mkdirat及0700；重命名用同父目录renameatx_np与RENAME_EXCL，不回退到会覆盖目标的普通rename。现有SDK sys/stdio.h和sys/attr.h已核对，目标API自macOS10.12可用；[Apple文档](https://developer.apple.com/documentation/foundation/urlresourcevalues/volumesupportsexclusiverenaming)和[官方XNU手册源码](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/man/man2/rename.2)说明独占重命名支持。实际范围仍为当前Mac的合成APFS目录，不承诺所有文件系统/故障设备行为。

同宿主注册表串行，项目内的多API操作还使用实例共享停写锁与独立文件操作锁；导出排他锁仍可停写。这些锁不约束外部恶意进程移动整个目录，前后检查不是文件系统事务、OS隔离或强fencing。源同名对象在检查后被外部替换等竞态仍需生产隔离设计；当前原型不得面向不可信多用户部署。

## 结果与响应丢失

状态为completed、failed或uncertain。failed只表示本宿主在系统调用应用前已拒绝；一旦系统调用成功，之后的权限/根身份/目标验证或fsync失败都归uncertain。不会为“回滚”而删除一个可能已被用户继续编辑的对象。执行后复查目标、源名缺失、父目录身份和授权，并同步父目录；这不等于真实断电或崩溃持久性已验证。

operationID同时标识一次预览和同宿主结果，重复提交同ID返回已有回执，不重复执行。结果最多32条、300秒，未知/他人/已清除返回notVisible/null。会话退出清除该会话预览和结果；API重建/重启不恢复批准或回执。失去回执的旧ID不能重新执行；必须检查目录后显式新预览，不能把notVisible当作“操作没发生”。

新增第15至17个固定消息previewFileOperation、commitFileOperation、fileOperationStatus。响应采用精确版本化DTO；意图和空字段明确编码。预览编码失败不登记可执行能力；提交完成但响应编码失败时，文件可能已改，宿主回执保留可供显式查询。查询不授予新客户端提交权限。

## 客户端与网页

具名客户端只提交本客户端获得的ready预览，提交参数固定confirmed=true；查询不会产生提交权限。同ID提交/查询串行，最多32个本地已知预览，关闭清理。一般传输丢失/超时沿用既有关闭行为，不自动创建新连接。仍存活连接上的固定业务错误可通过显式结果查询核对；已关闭连接不能伪造恢复。

file-operations.js借用显式来源，严格复制/验证意图与结果。控制器保存原ID和意图，响应异常进入uncertain，禁止重复提交；只有显式check调用查询，ready/notVisible都不能当成功。dispose丢弃迟到结果，不关闭共享客户端，也不撤销已应用的文件操作。

固定网页树独立提供相同预览/结果语义，创建、文件/目录改名确实改变该内存树；目录改名保留子树，父目录修订使旧续页/旧预览失效。身份退出和来源dispose清理状态。它不读写NAS，不证明真实路径批准或落盘。界面显示新建/重命名、冲突编辑、确认、结果和读取失败，不放置未实现的上传/删除等假按钮；只读身份禁用写入。实际DOM、焦点、确认弹窗和窄屏仍待正规浏览器验收。
