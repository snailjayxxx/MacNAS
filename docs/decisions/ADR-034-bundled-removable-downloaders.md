# ADR-034：默认内置且可移除的原生下载器

日期：2026-10-17。来源：本会话用户直接要求增加 qBittorrent 和 Transmission 安装支持，MacNAS 默认提供两者，用户可以删除。这是这两个第三方组件的明确准入；既有只读规划、111 父需求和优先级不改写。

MacNAS 发行物默认安装两个原生 macOS 应用，安装状态相互独立。用户卸载任意一个或两个以后，重新打开包管理器和再次初始化均不能默默装回。卸载只移除 MacNAS 管理的程序目录，保留下载文件、任务恢复信息、配置和离线安装包；手动重新安装使用本地已固定版本的缓存。网页卸载动作需显示包名和数据保留说明，由管理员明确确认；读者及恢复只读模式只可查看。

当前选择官网实际提供的 macOS 稳定包：qBittorrent 5.2.3 和 Transmission 4.1.3。版本、官方来源、SHA-256、bundle ID、程序名称和许可来源进入 `packages/downloaders.json`。qBittorrent 网站其他平台的 5.2.4 不作为 macOS 包版本。应用保留原始签名和许可资源；最低产品目标仍为 Apple Silicon / macOS 15+，这不等于已在 macOS15 系统运行。

原生包准备工具 `scripts/manage_downloaders.py` 只管理显式指定、首次新建的私有目录。`fetch-cache` 是发行构建步骤；`init`、`install` 和 `uninstall` 无须网络。初次安装先检查两个归档的完整 SHA-256，再以只读 DMG 挂载、精确包名、bundle ID/版本/入口、arm64 和 codesign 检查准备两者，全部通过才发布新目录。该工具使用现有 Python 标准库及 macOS 工具，不引入下载框架、包管理器或容器。

本机从外挂开发盘的私有目录挂载 DMG 首轮返回权限拒绝。将同一已校验的公开安装包复制至 `/private/tmp` 的随机私有目录后，可以只读挂载、检查和正常卸载；安装目标仍留在显式开发沙箱，没有更改安全权限。另一轮 lipo 参数顺序错误先行拒绝安装；真实工具检查后按其 input-first 语法修复。两轮失败和原源码均保留，不将其改写为成功。

程序、离线缓存和 data 目录分开；只允许两个已知包 ID，不接受任意脚本、下载 URL 或系统路径。移除时不杀进程，对打开的程序文件拒绝卸载。进程锁和原子收据替换协调本工具调用；失败状态显示 needsRepair，由显式安装或卸载处理，不宣称跨进程恶意写者/断电事务或生产授权保证。收据为宿主本地打包元数据，不替代 PostgreSQL 业务库，不进入旧 portable 格式。

网页通过独立 `downloaders.js` 展示显式 fixture 生命周期，保留现有合成环境提示，并明确操作不会修改本机应用。它不回退到真实主机，也不通过浏览器执行本地脚本。当前原生包工具与网页 fixture 分别验证；生产登录、套件宿主桥接、后台启动、BT 任务和 RPC/WebUI 端口属于后续接线。没有把准备应用包当作下载服务已运行。

测试和有限真机结果见 N-030 验收与阶段证据。旧 N-029 核心/测试/SQL/实际管道依赖保持；新增打包工具和网页改动由专属测试、实际隔离安装及新前端覆盖。复用完整原生回归时必须精确核对旧核心和实际执行依赖，不把新增包测试冒充新的 Swift 全量。
