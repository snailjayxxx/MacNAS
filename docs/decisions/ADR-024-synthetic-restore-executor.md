# ADR-024：独立目标批准与原条目恢复结算

日期：2026-10-16。状态：已实现并通过新完整自动回归，见[阶段证据](../evidence/n029-b2-2026-10-16.json)。沿用ADR-021/022/023的日志、预算、锁和单次移动约束，不修改已发布0001–0004。

B2复用已登记vault和同一个文件效果管线。恢复方向交换源与目标：源固定为历史slot/payload，目标固定为同库现存父目录及一个新名称。仍在实例共享门→vault独占锁→短DB事务顺序下，先固定FD和stamp/SHA，再prepared/armed提交读回，一次RENAME_EXCL，observed持久后严格同步两端并复核。私有协调器核验凭据仍是observed/completed/cancelled的唯一调用能力。

宿主分别签发恢复来源批准和目标目录批准，目标批准固定原始路径与物理目录身份。令牌绑定当前宿主、撤权代次、签发时注册字节及期限；目标批准不可通过普通用途发放方法构造。许可范围摘要包含两种批准ID和目标原始路径。旧目标目录被替换后，即使新目录路径相同也需重新批准。父目录的mtime变化不视为身份变化，允许无关文件合法增减；效果前有界扫描大小写/规范化冲突，效果后只核对固定目标和两端身份，避免无关目录增长遮蔽唯一后置证据。

条目始终归原始主体。只允许一个completed recycle对应的retained且无活动操作条目恢复；在原entry上追加restore operation并CAS entry revision。prepare/cancel restore都保持retained和字节，completed restore才转released；每次restore历史单独计operation数，不复用历史payload slot。catalog逐entry核对原回收完成、当前活动方向与phase、完成恢复数和已登记slot布局。任何可能执行但未解决的效果隔离该vault新准入，未知对象保留。恢复后的原文件再回收使用新entry和新slot。

缺post中断不会因源或目标目前看似吻合而自动续做/取消/释放。观察批准只读分类，新的写结算批准与当前有效独立目标批准可对匹配的已持久post补同步/CAS；跨宿主必须两种新批准。完成setter不会产生第二次rename，不改变原operation/entry ID。prepared取消只是元数据结算，无文件移动，所以专用取消批准和两端未移动证据足够，不取得目标写批准。

所有后置转账仍使用A预留行容量和B的有界索引CAS，强制事务同步提交及PG fsync/full_page_writes检查；4MB全库摘要超限不会丢弃已有文件效果的唯一证据。到期不自动清扫。released不等于网页整树空出容量，C必须联合可见/回收/上传复制预留实现共享计量。B2不接生产路径、后台删除或浏览器；真实SIGKILL不代表真实断电/跨Mac/强fencing。
