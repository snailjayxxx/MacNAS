# ADR-022：Schema4持久文件日志基础

日期：2026-10-16。N-029 A实现决策，自动验证通过；最终结果见[阶段证据](../evidence/n029-a-2026-10-16.json)。遵循[ADR-021](ADR-021-recoverable-recycle-journal.md)，范围见[验收矩阵](../plans/N-029-A-ACCEPTANCE.md)。

## 数据库与宿主基础

以新增0004交付recycle_entries、file_effect_operations及封闭SQL验证函数；旧0001–0003原字节不动。类型/列序/NULL/约束/索引、函数正文/属性/权限均检查，复合外键固定entry与活动operation关联，运行验证补跨表主体、实例、代次、来源及计量关系。SQL形状与证据只能证明数据库记录自洽，不能证明文件效果发生。

DurableFileEffectJournal是内部可信合成宿主基础，没有RPC、vault注册、来源/payload路径访问、rename或完成状态setter；它会读取受控实例元数据并创建既有`.instance.lock`协调锁。输入的stamp和来源标记由测试宿主提供，不是生产认证或文件批准。准备、幂等比较、CAS、容量准入和prepared取消在同一SQL事务中，通过固定transaction advisory lock串行；并发调用不能各自先读余额再超额插入。写入还持实例shared门，检查当前实例/代次/DB描述符/宿主模式及原始UTF8主体，提交后复查拒绝不代表事务回滚。

原主体/逻辑路径/幂等键以bytea精确保存；意图的SHA统一对PG jsonb::text规范值计算，不能把Swift紧凑JSON的SHA与PG带空格规范文本混用。旧记录ID和意图保持不变，同键相同意图只返回原记录，取消也不能复活；旧revision或不同来源标记不能推进。仅prepared可用明确命名的无执行者取消路径，armed/uncertain继续完整收费。B接入真实执行者前必须另审宿主批准、锁与正面的未移动证明，不能把此DB方法直接变成文件取消接口。

64MiB预留/保留、64个entry历史、256个operation历史、8个未解决操作同时生效；0字节也占历史/活动槽。整行4/8KiB和最坏终态证据空间在准备前检查，30天仅记录截止，不提供清理。A不开放observed/completed设置器，测试使用封闭SQL夹具构造这些行来验证约束和恢复准备，不声称文件已移动。

## 摘要与可携边界

摘要在同一个repeatable-read只读快照内先累计规范行长度，再有界聚合；语句10秒、完整规范文本上限4,000,000字节。PG18内置SHA256只回hex，旧版本投影保持原语义并与旧Swift路径交叉验证。Schema4把两张新表纳入完整语义摘要，schema_migrations按既有语义以经验证的版本链表示，迁移执行时间不作为业务内容。旧任务/事件仍可增长，本步骤不能保证所有旧写者永久维持总元数据预算；超限拒绝摘要/新日志准备而不截断。B执行真实文件效果前须重新审核最坏后置证据的准入保证。

Schema3→4在隔离候选执行，保留旧库及签名快照，用完整Schema3投影保护旧jobs/outbox，不只检查baseDataDigest。新增两表进入同一12表SHARE屏障。普通Schema4导出、候选发布/resume和回退要求新两表均空，且host-binding仅已知绑定/普通锁文件。A没有vault注册入口，未知字段/目录、任何回收历史（包括released/cancelled）都拒绝普通可携；旧1–3排除规则保留。数据库诊断快照可保留非空日志，但不成为包含payload的可携包，也不逆转文件移动。

`pg_restore --no-privileges`会重建函数默认PUBLIC EXECUTE。正常隔离导入在严格验证前仅撤销六个固定签名的该项权限；导入COMMIT后、日志推进前中断的候选，只能在已认证的databasePlanned阶段执行同样的幂等收紧。数据库未授予PUBLIC连接，也未安装套件角色。imported及后续阶段不自动修复权限，普通validate始终严格拒绝后续误授、函数替换或其它权限异常。

现有任务/套件/Bridge/CLI允许数据库3/4；DTO与固定RPC集合不增加回收能力。typed client固定首次schema，连接内变化拒绝，静态网页仍是Schema3内存fixture。生产浏览器连接、真实回收与恢复、SIGKILL文件核对、永久清理和后台扫描由B/C或更后阶段实现。

## 实际修正与证据要求

首次数据库运行发现跨表JSON提取后减ARRAY的SQL优先级错误，需明确括号。独立审查另找到权限验证只覆盖DML、漏TRUNCATE；实际合成误授反例证明套件可清空日志而校验未拒绝。修复后检查两套件对核心Schema的USAGE/CREATE、两新表全部8项权限及验证函数EXECUTE；保持真实红例和默认拒绝负测。原始失败、修复后定向、新未过滤全量、独立真实管道及PG关闭分别记录，不能用语法检查或定向通过代替完整回归。

完整定向运行还暴露了导入函数ACL的实际拒绝，以及两项新测试的基线/输入问题：无payload断言必须计入既有实例协调锁，长路径预算测试必须使用每分量不超过255个UTF8字节的合法路径。另一次新增测试漏写try导致编译失败，修正后重新运行；这些失败均保留。

二次独立复核的两项反例已在合成PG实际复现：删去版本4迁移行后，回退曾按版本3跳过新历史门槛并改写journal/binding；先临时放宽CHECK函数、写入坏宽行再恢复准确函数定义，验证曾仍通过，摘要按行数预留也漏掉实际超4MB。修复要求回退先验证候选完整当前Schema（仍允许有效的升级前旧版本候选），验证逐行重跑两封闭函数，摘要独立累计实际规范行大小并同时保留最坏后置证据预留。拒绝时不自动修数据、不截断或删除历史；这些一致性检查不是对恶意数据库管理员的强隔离。
