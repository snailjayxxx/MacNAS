C3C1规定完整账目格式及生命周期，C3B提供一个新建Schema6物理合成范围。本阶段将两者接到宿主和真实管道。它仍是ledgerOnly读取；owned只是账目状态，不证明当前载荷匹配，不测量磁盘可用空间，也不签发执行资格。网页接线与管理范围物理观察、执行消息仍分阶段交付。

## 独立批准与固定来源

宿主方法authorizeFixtureCapacityLedgerRead只批准本次API、模拟会话、原始UTF8唯一管理员、角色和模式。实例/代次、数据库/宿主及Schema必须等于API构造时锚点，物理范围与回收登记的原始元数据也须一致。仅支持既有、合法Schema6 TestLab范围，不能创建或认领范围。旧回收观察、物理inspect或写批准均不能替代账目批准。

批准最多8个会话，底层用途grant有1800秒期限；撤销、结束会话及替换批准使旧grant失效。每次批准生成新的sourceID：以每API随机密钥对长度分帧的会话、实例、代次、DB、宿主、Schema、原始主体、角色、模式、两份登记及本次grant身份/epoch做HMAC。公开context只含版本、fixture-host、持久scopeID、不透明sourceID和当前主体/角色/模式，不泄漏DB、路径、inode或能力对象。sourceID用于防错等值校验，不能作为认证或执行凭据。

两条只读消息为capacityLedgerContext（空参数）及listCapacityLedger（精确scopeID/sourceID）。批准和撤销都不在消息白名单。CLI须显式--approve-synthetic-capacity-ledger-read；默认不批准，读者不能使用该开关。当前恢复只读模式可获新的账目批准；模式变化使旧批准失效。

## 真实锁与只读快照

新ledgerRead用途在实际实例共享gate、vault flock、祖先FD/私有目录/登记字节检查后才能构造封闭permit。它跳过全载荷audit，仅核对范围绑定，写转换、旧执行入口和inspect入口均拒绝该用途。执行路径仍走原有完整物理核对，不能由调用方传入跳过audit的布尔参数。

完整列表使用一个REPEATABLE READ READ ONLY事务和一个有界查询。SQL同时匹配容量范围和完整物理绑定，按allocation UUID读取至多65条；第65条使整个投影拒绝，不截断或分页，不拼接独立totals()与allocations()。六项聚合由同一份最多64条记录计算，Native严格验证状态/revision/哈希、原始主体、顺序、每文件16MiB、合计64MiB、8活动槽及0字节收费语义。非owned哈希显式为null。

查询前、投影和响应编码后均核对会话/模式、当前批准、实际持锁身份、私有绑定和目录身份，完成前再次核对持久物理范围。失败仅拒绝响应；没有认领armed、重放文件效果、取消或释放费用。客户端先overview，再取得并固定context，创建模型不读账目；显式refresh才发一次列表读取。同一客户端context/list共用一个在途槽。来源变化关闭当前客户端，普通denied/expired保留旧列表并标过期；dispose清本地视图并忽略迟到，不关闭借用连接。传输断开/显式abort/超时仍沿用既有关闭政策。
