# 原生套件契约（N-006 / N-009 / N-010）

Manifest包含来源/版本/API区间、最低OS/架构、入口、权限、逻辑存储挂载、网络策略、资源预算和数据版本。当前只接受两个已知自研清单，支持Schema1、2和3；未知版本和越权声明拒绝。

- hello-diagnostics：独立Swift健康程序，提供合成崩溃/挂起/超量输出测试。
- sample-file-index：只读取显式授权的host-binding/fixtures合成目录，返回相对路径，拒绝链接逃逸。
- 注册、停用、卸载和健康状态由核心管理；卸载保留数据。不透明授权绑定实例、套件、注册epoch、权限和期限，撤销后旧授权不会因重新启用而复活。
- 业务API使用每实例每套件PostgreSQL角色。套件不能通过参数选择任意库、表或SQL；核心、其他套件及其他实例分别负测。
- 监督器对自己的可信子进程执行超时、输出上限、取消及运行中撤权；清理数据库/签名环境，使用独立临时HOME。输出有轮询间隔，不承诺瞬时写入绝不超量。
- Schema1→2→3使用内置版本化事务SQL，在隔离库中升级并保留源库、原快照与数据摘要。未知未来版本和降级拒绝，回退不删除旧数据。
- 生产接管、正式签名安装、自动重启策略、CPU/内存硬限制、OS沙箱及第三方安装未完成。同一OS用户下的可信程序与数据库角色仍是不同的信任边界。

事件API草案为event_id/sequence/topic/app_id/instance_generation/payload，持久确认/去重总线属于下一阶段。
