# 03｜分阶段实施与验收计划（P00–P14）

## 总则
- 每阶段不仅是界面/功能描述，还包含数据安全、工程边界、真实设备验证、故障恢复及测试证据；完整首版目标为97条父需求。
- 技术方案若受到苹果API、驱动、型号、只读测试或依赖规则限制，生成「阻塞报告＋可选替代＋需所有者决定事项」，不偷偷改目标、不声称成功。
- 代码可按依赖拆并行开发，但先完成核心授权、数据模型、模拟测试后再接真实磁盘/账户/公网。P06存储池是真实生产发布硬门槛，不因网页界面提前完成而豁免。
- 任何阶段的模拟验证、开发机验证和正式硬件/数据验证都需要不同状态字段。

## 进度与完成判据

每条父需求下继续拆子任务：`设计 → 实现 → 自动化通过 → macOS15验证 → 新版macOS验证 → Windows/iOS交叉验证(如适用) → 用户验收`。不适用项标 N/A并说明依据；阻塞项不得被改成完成。

## MIG-05 跨Mac迁移贯穿阶段（不等到P14才开发）
1. **P00/P02**：先定义Portable Instance Root、版本化导出清单、host binding抽象；构建两套隔离临时目录的跨路径恢复测试。
2. **P04/P05/P06**：所有卷/共享/池引用采用可重绑定的逻辑身份；移机前后枚举差异并预览，未经确认不启动写入；阵列移机单独验证。
3. **P07/P09/P10/P11/P12**：插件、同步客户端、相册索引和数据库都要提供一致性快照、跨路径恢复和迁移版本兼容测试；相册原件保持外部数据目录不变。
4. **P13**：迁移证书、域名、令牌、MFA和外部客户端时，明确需要重授权、切换入口、吊销旧会话，不自动更改生产域名。
5. **P14**：在两台真实Mac或真实旧新主机条件上完成导出、拷贝、重绑定、恢复、回退、安全停旧服务、断电恢复；只有文件目录测试不能标为真机跨Mac通过。

## 首版发布门槛
1. 97项父需求都对应真实子任务和完成证据，用户确认的研究子项可用可复核研究结论来验收，但不能仅用研究报告替代已承诺的可运行功能。
2. 固定布局一盘容错聚合池需要真实授权测试盘完成至少一次降级与重建故障测试；现在明确缺少该条件。
3. 备份独立于池、能做异地/其他设备恢复演练；丢盘/重建时仍不可误写或损坏原件。
4. M2与另一代目标机/系统兼容项逐个验证，不能用开发机成功替代未来硬件的实测。
5. 远程分享及管理按隔离原则通过安全检查，公开配置按专项授权实施。
6. **便携迁移硬门槛**：一个文件夹迁移可携状态；新Mac需重新安装/授权本机辅助服务并重新绑定外置卷与密钥；模拟路径迁移、跨Mac真实迁移、故障回退及防双主均有实测证据；**复制文件夹绝不自动迁移30TB原件**。
7. 3-8路专有摄像头、特定下载协议等未确认时记录覆盖缺口，不以模拟器算真机通过。
