## 关键策略

### 存储池候选（必须由 Codex 逐项证明，而不是默选）

1. **基于 Apple RAID 的组合布局**：研究能否用固定布局形成真正的聚合冗余池（例如分层镜像/条带或镜像不同聚合单元），并验证一盘故障仍可读、可写策略、重建过程及约束；不得推断嵌套结构在任意 macOS 版本通用。
2. **独立镜像加平台级逻辑目录**：可作为对照，但两组镜像挂同一个网页不自动变成一个文件系统卷；如果用户要求的是统一写入空间，这类方案必须标明不满足之处。
3. **自研文件级聚合冗余**：需单独架构评审，包含数据布局/事务原子性/碎片/校验/修复/冷热拔/恢复工具，评估长期数据安全责任；禁止以未经验证的自研RAID直接承载家庭原文件。

所有候选至少提供：可用容量公式（按具体盘尺寸），损失空间，允许故障集合，替换/修复步骤，是否依赖同容量盘，是否支持 APFS/ACL/xattr，典型资源占用，独立备份要求，支持的 Mac/硬盘接口。**不得执行创建/抹盘/重建操作，除非单独取得测试盘明确授权**。

### 智能相册

- 四个方向拆分为相似检测、同人分组、OCR 和自然语言搜图，不把人脸检测说成同人识别。
- 首版只采用苹果 SDK、本机 Apple 模型。模型可能受OS/硬件/配置制约；可用性不足时标明阻塞而非暗中调用云服务或第三方模型。
- 推理日志和流量验证要证明照片/特征不被上传。应用内提供功能关闭、索引删除、资源预算及结果纠错。
- 本地模型支持不意味着 M2/8GB 在整库处理时达到足够速度；用样本建立客观耗时/峰值内存/回收策略证据。

### 组件边界

- **NAS运行/发布物：**自研代码＋苹果能力；未经批准不引入任何第三方运行组件、库、模型、FFmpeg、数据库引擎等。
- **开发与测试：**第三方工具可列审查清单，**未经具体批准不得安装**，不得以编译内嵌规避运行组件政策。
- **Windows客户端：**可提出使用 Microsoft Windows SDK、系统服务和文件API 的独立方案，仍不默认允许其他第三方运行时。
- **第三方插件：**方案可以受理，但实际启用需要独立来源审核、兼容/权限校验和用户批准。
