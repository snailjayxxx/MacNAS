## 0. 环境只读检查（无需反复问用户已给的答案）
第一步在用户Mac mini上只读运行适当命令，确认真实情况并记录必要摘要：

```bash
sw_vers
uname -m
xcode-select -p
ls -ld /Volumes/MacNAS-Dev
# 仅只读检查明确的卷：
diskutil info /Volumes/MacNAS-Dev
df -h /Volumes/MacNAS-Dev
```

- 必须确认volume mount存在、设备确实是**外置SSD**、`APFS`（默认非区分大小写）、预期卷名`MacNAS-Dev`、没有被当作启动系统盘、不包含需要保留的旧项目，并确认有足够可用空间。`diskutil`显示的文件系统与设备角色为准，不凭`ls`判断。
- **如果未挂载、格式不符、路径被其他设备抢占、容量明显不符、权限不足或现有同名路径不确定：停止写入并报告；绝不自动格式化、分区或更改磁盘所有权。**
- 只读取机型、系统版本、目标卷和开发工具可用性，不递归扫描其它NAS卷、家庭数据或私人文件。无需上传系统序列号、密钥和私人路径。

## 1. 在已确认的开发盘下自行建立结构
在确认无冲突后，创建：

```text
/Volumes/MacNAS-Dev/
  MacNAS-Workspace/
    MacNAS/              # 本地Git项目：正式源码、SDK、文档、tests
    Build/               # 派生构建产物（可清理）
    TestLab/             # 模拟磁盘、合成图片和录像、fixture（无真实用户数据）
    DeploySandbox/       # 便携实例根的非特权模拟部署与迁移验证
    Evidence/            # 已脱敏的构建、测试和故障证据
```

- 先检查现有文件，避免冲突、覆盖、`rm -rf`；目录名仅建议，必要时在ADR中修改。
- 仓库已存在时读取HEAD/状态/AGENTS.md等，保留原改动；没有仓库则**允许在上面安全的工作目录中新建本地Git仓库**，不要自动创建远端Github、推送main或添加未知remote。
- 不把500GB SSD当作正式30TB存储池、不从该盘直接运行root/privileged helper。
- 先实现便携根目录规范，开发时即测试将`DeploySandbox/MacNAS-Instance`整体移到另一目录仍能恢复。
