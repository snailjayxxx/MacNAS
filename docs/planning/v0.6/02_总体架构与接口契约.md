# 02｜候选系统架构与接口契约

**性质：工程设计提案，不是用户已经批准的技术实现，也不是已经通过macOS 15真机验证的组合。**

## 系统边界

```text
浏览器（中文/日文，DSM式桌面）    iPhone客户端       Mac/Windows同步客户端
           │                          │                    │
           └──────────── TLS/HTTPS API +版本化协议 + 授权 ─┘
                                      │
               非root平台核心：鉴权·会话·目录注册·任务·通知·审计
                   │              │             │
            文件/同步/搜索       插件管理器        本机系统适配代理
                   │              │                    │
       指向受控目录的资源句柄   各自的服务进程    签名校验的XPC/IPC边界
                   │              │                    │
                多个卷      相册/备份/下载/NVR/家居    小而精的特权助手
                   │                                   │
            存储池适配层（待可行性证明）      macOS 原生共享/卷/账户配置
```

## 技术路线原则（需要 Codex 提出ADR并以机上验证）
- **原生应用和系统适配**：优先 Swift / Foundation / Network / Security / CryptoKit / ServiceManagement / DiskArbitration / ImageIO / AVFoundation / Vision / Keychain / SQLite系统接口等苹果提供的SDK。哪些确实适合在指定OS作为服务器使用必须原型验证。
- **网页**：自研的HTML/CSS/JavaScript单页桌面，支持窗口、键盘、移动适配、语言包与权限菜单。不得未经批准引入 Vue/React/Vite/第三方 UI、图标包或编译期/运行时依赖；如需类型检查工具，先提交仅开发工具准入单。
- **主服务**：非root本机进程；明确HTTPS、认证、会话、速率限制、CSRF与WebSocket安全边界。Network.framework 并非现成安全成熟的整套Web应用框架，不能凭有监听接口就宣称生产HTTP服务准备就绪。
- **特权代理**：仅执行明确列出的结构化、可审计动作；进程自身验证签名/来源；禁止提供shell、脚本和路径拼接执行器；网页、插件不能直接呼叫root命令。系统服务注册/卸载使用受支持的API；服务重启/注销状态分别测试。
- **数据库**：平台元数据与原始用户文件严格分离；是否使用macOS随附SQLite3及其部署ABI，由Codex实测并提交技术决策。密钥在Keychain，日志/备份不暴露凭证。
- **客户端**：macOS/iPhone用苹果原生API；Windows同步客户端允许以微软原生能力做方案，但仍需单列运行库、分发和版本要求，不可把其目标降为网页访问。
- **模型**：Vision可作为相似度/文本/检测的候选；Apple本机Foundation Models等高版本API走`#available`/capability探测，不能写成macOS15普遍可用或自动切入云端。对于只在新系统可行的方向，必须保留15的明确降级状态与阻塞证据。

## 核心资源模型（首版需要固定为接口契约）
- User / Role / Group / Session / Device / ShareMapping / ResourceGrant。
- VolumeIdentity / EnclosureIdentity / PhysicalMember / PoolLayout / PoolHealth / MountBinding / Library。
- FileIdentity：`library_id + volume_id + relative_path + stable_file_metadata`；不要以用户输入的绝对路径作为跨API资源ID。处理同名卷、符号链接、硬链接、Unicode、大小写碰撞与权限继承。
- Job / JobCheckpoint / IdempotencyKey / Event / Notification / AuditEntry。
- AppManifest / InstallBundle / RuntimeCapability / AppInstance / AppGrant / AppDataVersion。
- PhotoAsset / Derivative / EXIF / FaceCluster / OCRIndex / SimilarityVector / Album / ShareGrant。
- BackupPolicy / SnapshotManifest / CopySet / RestoreSession / IntegrityEvidence。
- SyncPeer / VersionVectorOrEquivalent / Tombstone / Conflict / RetryCursor。

## API与状态约定
- 前台接口路径可暂定 `/api/v1/...`；真实路径先写OpenAPI式接口规格，保证客户端版本协商。使用结构化错误码、请求ID、幂等键和审计关联ID。
- 用户/目录权限在后端每次验证，不能仅靠隐藏菜单。上传、下载、缩略图、搜索、媒体转码、后台任务完成通知、临时分享均必须检查有效权限。
- 系统危险操作“两阶段请求”：先预览 `dry_run` 及变更摘要，再携带短期授权令牌提交。高危动作还需要用户**显式系统操作批准**，这些规格本身不算批准。
- 异步任务必须具备 `queued/running/waiting_for_volume/paused/failed/completed/cancelled` 等明确状态；暂停或恢复不被实现时不可呈现可用按钮。
- 事件具备递增序列号、消费者确认、去重标识；断电/重启能恢复并避免重复破坏性操作。

## 文件路径和数据迁移
- 原始用户目录在预先授权卷上；平台配置与应用数据库独立；索引/缩略图可重建；卸载默认保留原文件。
- 盘离线时先阻止写入，恢复前重新核对卷标识，不能写入系统盘同名路径；跨卷移动先复制、校验，再删除源。
- 不在程序内部持有设备root权限；验证和备份数据库一致性与schema迁移。签名与发布包需要未来确定分发模式。

## 插件平台契约
- manifest最少字段：`id, vendor, version, api_range, minimum_macos, arm64, entrypoints, permissions, storage_mounts, network_policy, resources, migrations, signed_digest`。字段规范须由原型测试形成稳定Schema。
- 安装包与应用数据分开；支持离线安装/检查、依赖检查、启动/停止、健康检查、更新/回退、卸载保留数据、权限撤销。
- **重要**：manifest的权限声明不是OS级沙箱。第三方原生插件只有在实际限制文件/网络/进程能力的测试完成且经审核后才能开放安装。初期只接入自研可信套件，并准确声明隔离层级。
- 外部应用不得带root任意命令执行；真正需要系统能力须通过审核后的最窄平台API。

## DSM桌面功能契约
窗口管理（开关、层级、切换、缩放）、文件管理器、控制面板、套件中心、任务中心、通知中心、个人设置、响应式移动布局、支持中文/日文，以及匿名相册分享独立站点。不要复制DSM图标/商标/素材。


## MIG-05 从第一天起必须遵守的可携式实例契约
- **两种位置必须分开**：当前 `/Volumes/MacNAS-Dev` 是用户准备的**开发SSD**，不是未来生产实例强制位置。正式NAS实例的可携式根目录可以在新Mac上任选路径，所有运行数据相对该根目录解析。
- **Portable Instance Root**：实例目录内保留版本化清单、平台设置与数据库、插件包和应用数据、事件和任务必要检查点、逻辑用户/权限、备份策略、外部卷引用；不包括Mac系统Keychain/TCC/系统账户/实际LaunchDaemon注册，不默认包含30TB原始用户文件。
- **Host Binding**：单独保存机器特定的状态与重绑定记录（例如卷UUID、SMB本机用户UID/GID、已授权路径、应用签名/受信任helper状态、TLS密钥所在主机）。旧主机记录随包保留为**历史**，新Mac进行预检后生成新记录，不能将旧机器的授权当作有效。
- **绝不硬编码**：不能把 `/Volumes/MacNAS-Dev`、`/Users/<name>`、主机名、IP、机身序列号、挂载点、绝对数据库路径写进跨Mac配置或数据库业务行；在接口边界通过实例根和逻辑资源ID解析。
- **持久化协议**：数据库 schema、manifest、插件版本和迁移脚本均版本化；支持一致性导出（事务快照／应用暂停）、校验清单、完整性校验、原子恢复、幂等与回退。不能直接在运行状态 `zip -r` 打包打开的SQLite WAL作为有效迁移实现。
- **Secrets**：Keychain里的私钥、令牌和系统SMB凭据不作为明文搬迁；提供重新授权，确需迁移的秘密只在用户明确批准且采用审查过的加密备份方案时处理；迁移后旧会话和某些令牌需要失效/重签。
- **服务边界**：可携实例内可以包含受信任、签名完备的安装/恢复应用包，**不得**为了“一文件夹移动”让root daemon从普通用户可写的外置SSD直接执行不受保护代码。新Mac上的小型受信任helper及必要系统服务须按macOS受支持的ServiceManagement路径安装并接受系统授权。
- **防双主**：源Mac与目标Mac共用同一真实外置数据卷、同步数据库或远端目标时，必须有可验证的切换/租约/独占持有策略；仅复制旧锁文件不等于防止并发写入。目的端先以只读维护模式启动，经过切换批准后才可写入。
- **导出目录协议**：`instance.json`、`manifest.json`、`state/`、`apps/`、`app-data/`、`logical-storage/`、`restore/`、`portable-installer/`、`optional-cache/` 等只是推荐结构，最终ADR与接口测试决定细节。目录可以移动或改名；绝对路径只能存在可重建的主机适配层。
- **迁移模式**：`preview`（只读）、`export`（冻结/一致性校验）、`restore`（检查依赖/磁盘重绑定/授权）、`cutover`（明确所有者批准）、`rollback`（恢复旧机服务/恢复快照）五步，界面和CLI使用同一安全核心。

详细规范与验收用例见 `09_可携式目录与跨Mac迁移规范.md` 与 `11_迁移恢复与故障注入验收.md`。
