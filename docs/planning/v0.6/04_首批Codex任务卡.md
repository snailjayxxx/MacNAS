# 04｜首批 Codex 任务卡：现在即可执行的范围（仅已授权的开发盘）

**当前允许：** Codex对用户指定的 `MacNAS-Dev` 开发卷完成非破坏性存在性、文件系统、容量和真实卷身份检查，只有已核对为外置APFS后才在其下创建新工作目录和本地Git仓库；分析已授权仓库；新建规划文档；在明确可写的开发工作区建立脚手架/样例；纯模拟、测试fixture、临时目录、纯内存或自行创建/可删除磁盘映像上的非破坏性验证（磁盘镜像挂载前也先核实权限范围）。

**当前禁止：** 擅自安装新的常驻服务、修改启动项、SMB/本机账户、触碰外置存储盘、配置反向代理、公网、摄像头账号；创建/格式化任何真实阵列；执行 sudo；联网下载未批准组件。

### N-000 初始仓库与指令盘点
输入：本规划包；用户明确授权的仓库（目前未提供）。若在用户授权的MacNAS-Dev工作区未发现已有仓库，可**在该工作区新建本地Git仓库与项目骨架**，但不得擅自建立/推送远程GitHub仓库。先运行 `pwd; git status --short --branch; git rev-parse HEAD; git remote -v`（不主动输出敏感URL）。读取已有AGENTS.md/README.md/PROJECT_SPEC.md/ARCHITECTURE.md/PROGRESS.md/NEXT_TASK.md。若没有已有仓库，只能在已验证的 `/Volumes/MacNAS-Dev` 开发工作区中安全创建新本地仓库；不猜远端地址，不拉取未知仓库，也不得覆盖同名文件或其它已有项目。保留任何未提交内容。

验收：`docs/decisions/ADR-000-starting-state.md`、`docs/plans/STARTING_STATE.md`、`DEPENDENCIES.md`，记录确切命令、结果摘要和阻塞点；不得自动提交推送。

### N-001 需求导入和校验
输入：`data/需求总账_v0.6.json`，四轮原始JSON。生成需求索引、父子任务映射，自动检查所有111条ID唯一且优先级97/13/1、子任务有状态字段、历史原件hash未变化。

验收：例如 `python3 scripts/verify_requirements.py`（必须由Codex实际创建）；期望全通过，失败输出哪条ID。不得把97自动缩成少数示范项。

### N-002 macOS API能力探针（mock优先）
输入：Swift/AppKit/Foundation可用性、OS15部署目标；设计 `CapabilityProbe` 协议与模拟输入。API：共享读取、卷/磁盘柜枚举、launch服务注册状态、苹果本地Vision/模型支持探针。**真实探测前需要明确授权目标Mac和只读范围。**

验收：在没有真实Mac时，mock用例全部可运行；真机探测记录为未执行，不伪造环境数据。

### N-003 安全协议与最小特权边界
输入：本文件02和06。定义系统操作 `{operation, scope, preview, expectedState, token, requestId}` 的草案，示例仅使用虚拟磁盘/共享/账户。画出信任边界和10个负向测试，特别是路径越界、权限错配、CSRF、XPC调用方校验、重放。

验收：危险动作没有任意shell入口；模拟的拒绝默认行为通过；不存在root Web服务器。

### N-004 存储池架构对比（NO DESTRUCTIVE ACTION）
输入：固定聚合+1盘容错、5盘以上、多硬盘柜、30TB以上、当前无测试盘。比较：A 苹果原生磁盘集组合；B 镜像/拼接的受限拓扑；C 从零研发存储层（极高风险）。为每种给出可用容量公式、最小盘数、单盘失效模型、故障域、重建步骤、读取/写入受损范围、扩容和数据迁移。**不以RAID0或直接JBOD充当容错池**。

验收：ADR-Pool-001含选择前置条件；模拟物理盘/多个硬盘柜拔插事件以及恢复；缺真实测试盘标RED，绝不把磁盘镜像测试算物理故障通过。

### N-005 本地智能照片能力与macOS15兼容性
输入：仅苹果本机模型、macOS15最低支持，M2及未来芯片。建立4方向独立能力卡、Vision/相关API版本表、权限测试、人工测试图像/中日文测试文字；禁止调用云模型或上传图片。自然语言搜图不能等于按标签词匹配，除非有明确说明的受限模式。

验收：四功能均有准确性指标建议/样本标注规则/最低系统版本/失败或降级策略。只用官方或生成的测试素材，无家庭数据。

### N-006 原生插件接口和两个示例的接口规格
输入：APP-01..12。设计Manifest schema、权限、数据空间、升级回退与事件API。做两个完全分离的示例：`hello-diagnostics`（只读）与`sample-file-index`（授权测试目录）；在不修改核心的前提下能被注册和停用。首批全部自研，不开放不可信第三方native包执行。

验收：拒绝越权插件访问、服务崩溃主服务保持正常、卸载保留应用数据；所有能力验证类别单独记录。

### N-008 Portable Instance Root 与跨路径迁移原型（MIG-05，必须早期执行）
输入：`09_可携式目录与跨Mac迁移规范.md`。在**已验证的MacNAS-Dev测试工作区**构建无需系统特权的原型：目录版实例状态、manifest/schema版本、host identity分离、外部卷逻辑绑定、导出/导入预览、实例锁、校验与回退。使用模拟状态和两份不同目录，严禁读取正式照片库或真实Keychain/SMB系统账户。

验收：可将实例文件夹移动到名称和位置完全不同的测试目录，重新初始化仍恢复配置/虚拟套件和工作数据；数据库快照一致、断电中断恢复/重试可复现、状态校验错误时拒绝上线、未知卷只读/阻止写入、新旧实例同时活跃时阻止双主写入、任何secret未被明文导出；失败时旧实例完整。输出明确Mac真机/原生授权尚未验证。
