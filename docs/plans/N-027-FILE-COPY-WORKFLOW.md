# N-027：受控文件复制与后续文件管理

接续N-025/N-026的有界传输能力，继续按Finder与File Station的日常流程开发。当前新建/改名、单文件上传/下载和目录重读都只在明确的合成范围内验证；复制、移动、回收站、共享权限及大文件可靠传输仍有实际缺口。SYS-09远控保持很后期。

## 下一可实施范围

先交付单个常规文件的复制闭环：选择有权来源 → 选择有权目标目录/名称 → 预览冲突与大小 → 明确确认 → 私有暂存与分块摘要 → 不覆盖发布 → 核对结果与重读。名称、来源、目标资料库及父目录在预览时固定；不能从下载、上传或mkdir/rename的能力推导额外权限。新增宿主明确的复制批准和严格消息方法，不接收任意宿主根路径。

复用经过验证的描述符读取、私有暂存和RENAME_EXCL发布原语时，也要重新设计“两端来源与目标同时有效”的上下文；来源变化、撤权、目录替换、同源同目标、冲突、跨设备、不完整暂存、发布后核对失败均有独立语义。复制永远不删除来源。不能借已有任意路径接口或先做“复制完成”按钮再补效果。

若第一步沿用16MiB原型预算，必须明确只支持单文件且在真实合成目录测试，不称为目录树、批量或大型NAS复制。跨设备流式复制、进度任务、GB级、崩溃/重启恢复需要外部效果协调日志与新的版本化Schema迁移；现有Schema3的事务内任务不保证文件副作用exactly-once。历史0003、旧源数据和原规划包不得修改。

## 随后的流程

1. 复制稳定后推进可恢复回收站，先定义同卷私有位置、原路径/主体、恢复冲突、容量与保留期，以及崩溃协调。合成环境外的删除、永久清理、真实账户/ACL均不由本轮开发自动授权。
2. 移动先区分同卷重命名与跨卷复制后删除；只有来源仍匹配、目标经验证且删除阶段另有批准时，才设计来源处理。不能用普通覆盖式rename或把取消当已发布文件回滚。
3. 共享权限和生产认证/helper完成前，网页继续明确标注合成范围，不向正式NAS路径写入。
4. 控制面板/网络按[详细DSM对照](DSM-CONTROL-PANEL-NETWORK-REFERENCE.md)推进独立只读适配器：接口/地址、默认路由/DNS、服务能力、资源状态与变更来源。读取与配置分开，先做可验证真实数据，不改当前Mac的IP、代理、SMB、防火墙或系统服务。

## 验证和接续纪律

继续扩大合成文件能力前，补充整个内存树的总字节配额；当前只有4096项的条目上限和每次/在途传输预算，不代表已发布数据的整体内存调度。共享客户端的连接管理也需覆盖关闭窗口时仍未返回的预览头、本地能力最终回收和长期反复开关；当前普通连续45次传输已验证，但它不能代替所有中断交错验收。不把有限预算拒绝自动变成重连/接管或放大上限。

修改原生/SQL/核心测试或嵌入Node依赖后，按QA守卫重新运行匹配的完整验证；只修改网页时可沿用精确未变化的核心基线，前端收据必须新跑。每阶段记录成功、实际失败和正常清理，阶段完成后按用户长期授权中文提交/推送dev/bootstrap；不合并main、强推或改历史。

46项实际网页仍由Codex在正规权限恢复后执行；模型、DOM结构替身和管道不代替浏览器。没有新状态时不重复浏览器权限请求，不换通道绕过。真实跨Mac、物理盘、断电、macOS15运行与生产部署均另验。
