# N-017下一步：网页任务页展示与业务适配

N-016提供了固定上限的实时任务页，但当前网页仍调用内存fixture的完整listJobs；具名客户端没有加入HTML，也没有可信浏览器传输。下一步将任务展示从“整份数组”调整为显式页交互，不启动新的NAS服务或绕过浏览器限制。

1. 阅读现有desktop.js/model.js、DESKTOP_API和ADR-009/010，设计当前fixture与具名客户端之间的展示映射；普通标题/文件名用文本，不能当作文案键，不伪造任务时间或实盘容量。
2. 任务中心采用固定页大小、明确的下一页/重新读取、空页/末页/加载/失败状态及内存上限；统计来自独立overview，不能把已加载页数量当作任务总数。搜索/过滤只覆盖已读取范围时必须清楚标示，不能假称全库搜索。翻页是实时读取，游标过期/丢失需显式重扫，不自动全量聚合。
3. fixture实现与契约一致的版本化有界页，保留显式演示来源。为具名客户端建立可测试的适配边界，禁止缺少可信传输时自动伪装连接成功或回退fixture。是否实际加载bridge-client.js须有清晰入口及测试，当前没有生产身份或浏览器IPC，不凭空增加HTTP/WebSocket端口。
4. 覆盖身份切换、关闭窗口/会话、迟到响应、游标失效、取消后当前页刷新、普通文本标题、读者/恢复及空页；只用合成数据、现有Node工具和必要的Swift管道，不能以源码测试冒充DOM/浏览器验证。
5. 更新中日文提示、接口/ADR、证据、有限需求子记录及接续文档，按改动范围执行测试；若Swift/核心测试变化，补定向及未过滤回归。独立功能完成后沿用用户授权，中文commit并正常推送dev/bootstrap。

网页窗口W01–W10及完整视觉/键盘/窄屏清单仍全部待测。把本轮新增页面交互加入回家清单；用户主动恢复浏览器验收前，不尝试设置、浏览器或预览。此前127.0.0.1:8766临时静态预览和访问授权保留，无须再问。
