# N-025：有界分块上传与下载流程

接续N-024已验证的短文件操作流程，下一阶段优先补齐文件中心的传输能力，继续参考DSM/File Station日常操作。目标是实际授权目录内的传输链，而不是只加上传/下载按钮。实施前先重读N-024结果与文件系统/授权边界，SYS-09远控仍很后期。

## 用户流程

上传：选择有权目录 → 选择文件 → 查看目标与名称冲突 → 分块传输与进度 → 验证 → 不覆盖式发布 → 重读目录。下载：选择有权文件 → 获取受限下载会话 → 分块读取 → 显示进度/取消 → 校验完整性。读者的下载和管理员上传分别授权，不能因能列目录就取得写入或任意路径权限。

## 与DSM日常流程的对照

2026-10-16核对[群晖File Station上传说明](https://kb.synology.com/en-eu/DSM/help/FileStation/upload)：参考目标包括选择/拖入本机文件、明确同名处理，以及可查看的上传进度和速度。MacNAS先交付不覆盖发布与明确冲突；跳过、覆盖、批量和目录拖放仍需各自后端语义及浏览器验证，不直接照搬网页声称的大小或浏览器能力。取消后应能解释已传输、已暂存及已发布的区别。

[File Station设置说明](https://kb.synology.com/hu-hu/DSM/help/FileStation/settings?version=7)将创建、上传、下载、删除、改名、移动、复制和属性变更纳入活动日志。MacNAS后续也要在已有日志需求下记录主体、原意图、结果及失败阶段；短时内存回执不能充当持久审计。此处是后续设计要求，不表示N-024已经实现审计或完整传输队列。

## 实施要求

- 大文件按固定字节预算分块、背压及受众配额，不放进单个JSON响应或无限内存数组；单文件、并发、临时空间与句柄总量都设上限。不能把1MiB样例读成功当作大型NAS规模验收。
- 当前stdin/stdout桥接请求只有64KiB预算，JSON编码和块边界必须纳入计算。它可证明受控合成传输协议，不能作为大文件生产吞吐证明；真实浏览器数据通道还需要认证、流式传输、带宽/空间限制和完整性验证，不能仅放大旧JSON上限或启动未授权服务来补齐。
- 上传先进入受控的宿主暂存区，边传边校验，不先创建目标假成品；发布使用明确的原目录身份、意图和不覆盖条件。取消/中断只清理属于该会话的暂存对象，不删除用户目标或未知文件。
- 下载绑定打开的文件身份与内容标记；源替换、撤权、掉线/重绑或过期不能换成同名新内容。明确实时文件读取与一致性快照的差别。
- 文件传输/外部效果不能直接借用现有仅数据库事务内完成效果的任务种类。需要持久进度/重启恢复时设计新的版本化Schema迁移、外部提交日志和协调机制，旧源库/数据与升级回退均需验证；不得直接改写历史0003迁移或给Schema3暗加表。
- 协议只接受逻辑资料库、相对路径、会话令牌及有界块，不能增加任意绝对根/系统命令/自动批准接口。继续采用PostgreSQL18，无替代引擎、新第三方组件或生产监听。
- 当前静态页面仍不连接NAS。先验证Swift核心与真实合成管道，再接具名客户端/网页演示；实际浏览器文件选择、下载权限、Blob生命周期和取消必须另验，不能借模型绕过已保存权限拒绝。

Apple的[有界读取](https://developer.apple.com/documentation/foundation/filehandle/read(uptocount:))和[可抛错写入](https://developer.apple.com/documentation/foundation/filehandle/write(contentsof:))文档提供基础I/O语义；这些同步方法本身不提供传输协议、断点恢复或任意文件系统I/O的硬超时。分块数、字节数、结果与重放验证由MacNAS协议负责，不能把“调用了有界读取”视作整条链已经有背压或可取消。

## 接续控制面板

文件传输形成完整链后，按DSM控制面板/网络对照推进独立只读的接口、地址、DNS/路由、服务与资源状态采集，再实现生产认证、系统helper与配置事务。不要为演示修改当前Mac的IP、代理、SMB、防火墙或远程控制设置。

## 验收

合成中日/Unicode名称、空文件/大文件、多块/最后一块、冲突、取消、超时、配额、磁盘满、源变化、撤权、断连后结果未知/重启恢复分别留证。原生、真实管道、模型、静态策略、DOM和真实部署结果分开；32项历史加FO01–FO06共38项网页待测持续保留。
