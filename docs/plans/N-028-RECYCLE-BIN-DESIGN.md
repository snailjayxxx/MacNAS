# N-028：可恢复回收站的设计接续

单文件复制之后，下一阶段先设计并验证可恢复回收站，不直接启用永久删除、正式NAS路径或系统垃圾桶。Finder/File Station的业务目标是删除前明确确认、能看到原位置及操作者、能在冲突时安全恢复；界面按钮必须有真实合成效果和可核对结果。

## 先确定持久边界

1. 明确同卷私有回收位置、逻辑资料库/相对原路径、来源身份、原主体、操作ID、保留期及容量上限。读取批准、上传/复制批准和mkdir/rename批准都不能代替独立回收/恢复批准。先只在新建明确批准的合成APFS目录操作，不触碰家庭文件或正式NAS。
2. 移入回收站与恢复涉及文件系统和PostgreSQL两个提交边界；先设计可重放的外部效果协调日志、阶段与崩溃核对，不把现有数据库事务内任务说成文件副作用exactly-once。
3. 若持久化元数据/任务，新增0004及对应版本化迁移，明确Schema3源库保留、独立候选升级、导出/恢复/回退与全部持久表的停写/摘要覆盖；不修改0003、原规划和旧源数据，不暗加表。
4. 定义“效果已发生但回执未写”的uncertain语义：按固定inode/设备/内容标记及受控名字核对，身份不明保留，不删除、不覆盖、不凭路径存在就接管。取消只能在可证明未移动时取消，不能承诺撤销已发布外部效果。

## 合成验收

先单常规文件、同设备、受限容量/条目/期限，再考虑目录。覆盖预览取消、撤权、同名冲突、目标替换、链接/硬链接/特殊文件、满额、进程两处SIGKILL、效果先于日志、恢复到原路径的冲突和重复请求。永不覆盖现有文件；恢复冲突要求重新选择/预览。永久清理及真实保留期后台清扫不在该设计自动授权内，另行定义。

前端沿用同一显式合成树和来源/控制器生命周期；原生及Node→Swift管道另使用批准的新建目录。所有原生/嵌入依赖改变后重跑精确匹配的新完整基线，并保留实际失败和测试库关闭收据。浏览器52项仍待正规权限恢复，不用替身或管道代替。

跨设备移动仍是另一阶段，只有目标完整验证且来源仍匹配、删除阶段独立批准后再设计源处理。之后共享权限与控制面板/网络独立只读适配器继续按既有DSM对照推进，不改当前Mac的IP、代理、SMB、账户、防火墙或系统服务。Intel支持以后再做，SYS-09网页远控仍很后期。
