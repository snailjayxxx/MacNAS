# N-015下一步：桌面业务DTO与有界客户端

N-014已经实现通用request及宿主分发器。下一步可独立完成完整业务DTO校验与具名客户端，继续使用合成CLI管道验证，不需要启动浏览器、修改设置或新依赖。

1. 按DESKTOP_API逐项验证overview、任务、事件、资料库、目录项与文本结果，检查必需字段、可选字段、类型、状态、范围和相互关系。未知数据拒绝，不把宿主返回的任意对象直接交给DOM。
2. 用户名、任务标题、文件名及文本一律保留为普通数据；i18n键来自固定集合。明确处理缺少更新时间、物理容量未知和逻辑估计值，不能伪造生产信息。
3. 给现有业务调用提供具名方法，固定方法/参数构造及业务幂等键生命周期；不允许客户端自报角色或创建宿主身份。fixture适配器和真实宿主客户端仍明确区分。
4. 实现有界等待、传输关闭/取消及旧连接响应丢弃。连接与请求ID序列共同管理，重建客户端时保留序列或使用新前缀，避免在旧宿主重放。重试写入须新请求ID、相同业务幂等键；连接失效报错，不自动回退演示成功。
5. 负测覆盖损坏DTO、越界整数、未知状态、HTML内容作为数据、身份/模式不匹配、响应关联和超时后迟到响应。用独立Swift管道和私有PostgreSQL验证真实字段。
6. 如改核心或标准脚本则重新运行适当全量回归；否则复用字节一致的最新核心收据并跑客户端和管道测试。更新需求有限子记录、ADR、PROGRESS及NEXT_TASK。

保持未完成：浏览器DOM与视觉验收、生产认证/宿主调用方信任、真实盘和文件授权、任务/事件/大目录分页与稳定游标。分页需先说明实时列表与一致性快照的区别，再设计边界和资源限额，不把当前响应预算当作大型NAS扩展性证明。
